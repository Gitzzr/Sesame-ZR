# 「一天一次」任务：机制、清单与核对台账

> 配套：[`architecture.md`](architecture.md)（离线/暂停状态机见 §11）、[`user-guide.md`](user-guide.md)（界面上的入口）、[`../TODO.md`](../TODO.md)
>
> 本文是**唯一维护入口**：新增/调整「每日一次」限制都在这里登记。

## 1. 为什么需要它

蚂蚁系的多数任务**服务端一天只认一次**，但模块是按轮次反复跑的（默认约 50 分钟一轮）。
不做限制时，同一个任务当天会被重复处理几十次：

| 任务 | 2026-09-28 当天次数 |
| --- | --- |
| 庄园任务[秋叶月饼任务] / [完成 N 笔旧衣回收] / [逛闪购外卖 N 元起吃] | 各 44 |
| 庄园任务[到店付款] | 40 |
| 绿色打卡🍀[各项] | 46 |

代价是**白跑请求**（在风控窗口里放大请求量）与**日志被淹没**。

但「限制」本身有反作用：一旦把某个**没成功**的任务误判成"今天已完成"，它就会整天不再执行，
而且事后无从发现。所以本文描述的不只是限制，还包括**核对机制**。

## 2. 现有机制（不要另造轮子）

| 机制 | 粒度 | 说明 |
| --- | --- | --- |
| `Status.hasFlagToday` / `setFlagToday` | 任务级 | 标志存在 `status.json` 的 `flagList`，**跨日整体清空** |
| `farm::task::limit::$bizKey` | 任务级 | 庄园任务：**服务端返回 `309 已达上限` 或本地判定成功**后置位，当天不再处理 |
| `EcoLife::tick::$actionId` | 任务级 | 绿色打卡：逐项锁定，已成功的不再重复提交 |
| `CustomSettings.onlyOnceDailyList` | 模块级 | 「选中每日只运行一次的模块」，**默认关闭**；默认名单 7 个：`antOrchard` / `antCooperate` / `antSports` / `antMember` / `EcoProtection` / `greenFinance` / `reserve` |

**铁律：只在服务端返回成功时锁定。** 失败、未受理、状态未推进一律不锁，当天继续尝试。

## 3. 核对机制（防止「限制了却没完成」）

因为 `flagList` 跨日清空，第二天看不出「昨天限制过什么、有没有完成」，所以额外做了一层台账：

| 层 | 位置 | 用途 |
| --- | --- | --- |
| 台账文件 | `config/<userId>/daily_once.json` | 记录每次**首次成功**（`flag` / 名字 / 时间），保留 **7 天**、跨日不清 |
| 代码 | `task/DailyOnceAudit.kt`（纯逻辑部分可单测） | 写入与读取台账，`merge` / `trim` / `dayKey` 均为纯函数 |
| 界面 | 日志中心 → 今日完成 → **「每日一次」区块** | 列出当天已锁定的项与首次成功时间 |
| 日志 | `record.log` 的 `📌 每日一次已锁定：… \| flag=… \| day=…` | 可按天 grep 回溯 |

**第二天怎么核对**：打开「今日完成」，看「每日一次」区块里有哪些项。

- 出现了 ⇒ 该任务当天**确实成功过**一次，限制是安全的；
- 本该有却没出现 ⇒ 它当天**根本没成功**，需要检查是不是被误锁（或服务端本身没给）。

台账保留 7 天，也可以直接看文件：

```bash
adb shell cat /sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/config/<userId>/daily_once.json
```

## 6. 新增一项「每日一次」的步骤

1. 确认该任务**服务端确实一天一次**（看日志里是否出现 `309 已达上限`、`剩余次数`、`已完成` 等信号）；
2. 在任务的**成功分支**里，先 `Status.setFlagToday("<前缀>::<标识>")`，再
   `DailyOnceAudit.record(UserMap.currentUid, flag, "可读的名字")`；
3. 在任务的**入口**加 `if (Status.hasFlagToday(flag)) return/continue`；
4. 命名约定：`<模块或功能>::<语义>::<对象 id>`，例如 `farm::task::limit::SHANGOU_xiadan`、
   `EcoLife::tick::photoguangpan`；
5. 补单测（纯逻辑部分）并更新本文的 §4 / §5；
6. 第二天按 §3 核对一遍，确认「锁定的都真完成了」。
