# 大号列表配置（好友名单一键套用）设计

> 状态：已实施（2026-09-23），已在 K50 完成端到端验证。
> 实施记录见 [`../plans/2026-09-23-friend-list-preset.md`](../plans/2026-09-23-friend-list-preset.md)。
> 前置功能：[`2026-09-23-account-preset-design.md`](2026-09-23-account-preset-design.md)（账号档位一键切换）。

## 背景

各业务模块有自己的「好友列表」设置：浇水给谁、赠送道具给谁、帮喂谁家的小鸡、抢谁的宝箱……
一共 **26 项**。问题是：

1. 想把这些功能都指向**同一个**账号（典型场景：小号服务大号）时，要逐个功能打开列表去勾人，
   26 个项目里翻一遍，既繁琐又容易漏；
2. 这些名单**语义并不一致** —— 有的填进去表示"对这些人做某事"，有的表示"**不**对这些人做某事"
   （例如「不收能量」），还有一个是把对方从"被收取对象"改成"被保护对象"。填错方向会得到相反效果；
3. 「名单填了」也不等于生效：部分名单被一个**独立开关**门控（赠送道具要开「赠送道具」、
   一起拿饲料要开「一起拿饲料」…），开关关着时名单完全不起作用。

## 目标

- 提供两份**持久化的关系名单**：**大号名单**、**小号名单**。标记一次，之后复用。
- 一键把「大号名单」套用到各功能的好友列表，免去逐项配置。
- 沿用既有的一键入口（设置页 →「账号档位（大号 / 小号）」），不新增入口。
- 把"填对方向""开关要跟着开"这两件事写进**可执行的策略表与单测**，而不是靠人工记忆。

## 非目标

- 不改任何业务任务的实现逻辑，也不改 `ModelField` 结构。
- 不做"自动识别哪个好友是大号"，关系名单由用户显式指定。
- 不做按功能逐项挑选的精细界面（保持一键；个别不想要的项事后单独改即可）。

## 数据基础：26 个好友名单字段

判定依据是**候选集**：只有候选集为 `AlipayUser::getList`（支付宝好友）的字段才算好友名单。
以下候选集一律排除：`AlipayBeach`（海域）、`CooperateEntity`（合种 ID）、`VitalityStore` /
`MemberBenefit` / `ParadiseCoinBenefit`（商品权益）、`AreaCode`（区划）、`ReserveEntity`（保护地）、
`farmFamilyOption`（家庭选项）、`listPropGroupOptions`（道具类型）。

按**填充语义**分四类：

| 分类 | 数量 | 填进去的含义 | 字段 |
| --- | --- | --- | --- |
| `SERVICE` 服务类 | 11 | 对这些人做某件事，**消耗自己、利于对方** | 浇水、赠送能量雨、赠送道具、复活能量、帮喂小鸡、一起拿饲料、送麦子、帮抽卡、送卡片、助力好友（农场 / 新村各一） |
| `EXPLOIT` 索取/干扰类 | 10 | 对这些人做某件事，**损人利己** | 雇佣小鸡、通知赶鸡、抢好友、摆摊、贴罚单、丢肥料、邀请摆摊、邀请开通、请走小摊黑名单、清理好友海洋 |
| `EXCLUSION` 排除/豁免类 | 4 | 名单内的人**不做**该动作（填人 = 相反效果） | **不收能量**、遣返、家庭不邀请、请走小摊白名单 |
| `PROTECT` 保护改写类 | 1 | 把对方从「被收取对象」改成「被保护对象」 | `AntForest.alternativeAccountList`（显示名「小号列表」，实为复活能量保护名单） |

### 门控开关（"名单填了不生效"的坑）

| 名单 | 生效所需开关 |
| --- | --- |
| 赠送道具 | `AntForest.giveProp` |
| 赠送能量雨 | `AntForest.energyRain` |
| 一起拿饲料 | `AntFarm.getFeed` |
| **送麦子** | `AntFarm.visitAnimal`（挂在"到访小鸡送礼"下，容易误判为"无门控"） |
| 帮抽卡 | `AntDodo.collectToFriend` |
| 遣返 | `AntFarm.sendBackAnimal` |
| 排队/贴罚单/丢肥料/邀请摆摊/请走小摊/雇佣/通知赶鸡/抢好友/清理海洋 | 各自的同名开关 |
| 浇水、帮喂小鸡、送卡片、助力好友、不收能量 | 无门控，名单非空即生效 |

> 「选择 + 计数」型名单（浇水 / 帮喂小鸡 / 送麦子）的值是 `Map<userId, Int>`，
> 其中 `Int` 是**每日执行次数**，`≤ 0` 会被任务直接跳过 —— 一键填充必须给正数，取最保守的 **1**。

## 配置结构

### 1. 两份关系名单（新增设置项）

放在「基础」页签（`BaseModel`），按账号隔离，随 `config_v2.json` 落盘：

| 字段 | 显示名 | 用途 |
| --- | --- | --- |
| `mainAccountList` | 大号名单 \| 供各功能一键套用 | 套用到小号档的服务类名单；并写入小号档的排除名单 |
| `subAccountList` | 小号名单 \| 供各功能一键套用 | 大号档据此把排除名单里的残留小号**移除** |

> ⚠️ 命名注意：`AntForest.alternativeAccountList` 的显示名也叫「小号列表」，
> 但它是**复活能量保护名单**（且 `monday` 变量恒为 `true`，实际是唯一生效的那份）。
> 新字段刻意叫「大号名单 / 小号名单」以示区分。

### 2. 分类策略（`AccountFriendListPolicy`）

纯策略、无 Android 依赖，登记上面 26 项 + 门控 + 计数默认值，并给出两档的填充规则与隔离自检。

## 数据关联方式

一键应用的写入规则 —— 不是"把名单铺上去"这么简单：

| 目标账号 | 排除类名单（不收能量…） | 服务类名单 | 索取/干扰类名单 | 门控开关 |
| --- | --- | --- | --- | --- |
| **小号**（套用「大号名单」） | 写入**大号名单** → 不偷大号 | 写入**大号名单** → 只服务大号 | **清空**（即便是大号也不该做） | 按需**打开**（赠送道具 / 一起拿饲料 / 送麦子 / 帮抽卡） |
| **大号**（套用「小号名单」） | **移除**小号 → 大号要收小号能量 | 不动 | 不动 | 不动 |

两条硬约束：

1. **小号侧**：小号档不得把「大号名单」以外的账号写进任何服务 / 索取名单 —— 小号只对大号动手，
   不波及第三方好友。
2. **大号侧**（用户明确要求）：大号需要收取小号的能量，所以「不收能量」这类排除名单里
   **绝不能出现小号**。大号档不但不写，还会主动把小号从现有名单里**剔除**。

`PROTECT` 类（复活能量体系）两档都**不碰**：小号档该体系整体关闭，填了也是死代码。

## 交互流程

沿用既有入口，四步：

```
设置页 →「账号档位（大号 / 小号）」
  → ① 选目标账号
  → ② 选【大号推荐配置】/【小号推荐配置】
  → ③ 选关系名单（复用设置页自己的 ListDialog，带搜索 / 全选 / 反选）
        默认勾选上次保存的标记；从未配过时默认勾选「本机其他已载入账号」
  → ④ 确认页（列出将套用的名单数量与名称、以及大号档将移除小号的说明）
  → 一键应用 → 落盘 + 广播重载
```

第 ③ 步的勾选结果会写回 `mainAccountList` / `subAccountList`，**下次直接复用**，这就是"免逐项配置"的落点。

## 自检

`AccountFriendListPolicyTest`（11 项）：

| 用例 | 断言 |
| --- | --- |
| 分类表共 26 项且无重复 | 计数 + 无重复 |
| 每一项的字段 code 在主源码中都存在 | 挡笔误 |
| 每一项的候选集确实取自 `AlipayUser` | 挡"把商品/海域当好友名单" |
| 主源码里的好友名单字段都已登记 | 反查完整性，新增设置项漏登记会失败 |
| 小号档要填的名单其门控开关都会在档位里被打开 | 挡"填了不生效" |
| 小号档不得把非大号账号写进服务或索取名单 | 约束 1 正反用例 |
| 大号档不得让小号残留在排除名单里 | 约束 2 正反用例 |
| 不收能量名单是小号档唯一且必须的排除落点 | 大号档取值必须是「不覆盖」 |
| 复活能量体系在小号档不参与名单填充 | 独立体系隔离 |
| 索取干扰类名单在小号档一律清空 | 且不得出现在填充列表 |
| 选择计数型名单都给了正的默认次数 | 防"次数 0 导致任务跳过" |

## 边界

1. **只填登记在案的字段**，找不到的记入 `skipped` 并回报，不静默失败。
2. **关系名单为空时保持保守**：不打开白名单开关、不改动任何名单（避免"看起来配好了其实半开"）。
3. 一天内多次套用是幂等的（写入固定值，不是追加）。
4. 别名冲突：新字段叫「大号名单 / 小号名单」，不与 `AntForest` 的「小号列表」混用。
