# 账号档位（大号 / 小号）一键切换设计

> 状态：已实施（2026-09-23）。实施记录见 [`../plans/2026-09-23-account-preset.md`](../plans/2026-09-23-account-preset.md)。

## 背景

本模块的绝大多数「蚂蚁系」功能都会以**好友**为操作对象：收好友能量、一键收取、Pk 榜收取、浇水、
合种浇水、雇佣好友小鸡、抢/训练好友、贴罚单、丢肥料、收取好友金币、帮好友抽卡、领好友礼盒……

当大号与小号互为好友、且两边都跑本模块时，默认配置会让它们**互相收取对方资源**。
更具体地说：小号开着「收集能量」「一键收取」时，会直接把大号已经成熟但未收取的能量球收走 ——
这是用户明确要避免的。当前版本没有任何机制阻止这件事，用户只能手工逐项关闭，既繁琐又容易漏。

## 目标

- 提供两套**独立、完整**的配置方案：大号档（全功能）与小号档（隔离）。
- 一键切换，不需要逐项点开关。
- **硬约束：小号档位不得包含任何可能窃取或消耗大号资源（如能量）的设置项**，两套配置资源隔离、互不影响。
- 该约束必须是**可校验**的，而不是靠人工 review；后续新增设置项时若破坏约束，测试必须失败。

## 非目标

- 不做「按账号自动识别大小号」。档位由用户显式选择，避免猜测。
- 不改任何业务任务的实现逻辑，也不改 `Model` / `ModelField` 的既有结构。
- 不覆盖调度、日志、时区等基础设置（见下文「不干预项」）。

## 核心概念

### 档位（PresetTier）

| 档位 | 代码 | 定位 |
| --- | --- | --- |
| 大号 | `main` | 主力号全功能档：开启各模块的收益与进度类能力 |
| 小号 | `alt` | 小号隔离档：关闭全部跨账号功能，只保留纯本账号操作 |

### 资源作用域（FieldScope）

每个设置项标注一个作用域，这是整套隔离保证的基石：

| 作用域 | 含义 | 档位处理 |
| --- | --- | --- |
| `SELF` | 只作用于本账号的数据与资源 | 两档都可自由开关 |
| `CROSS_ACCOUNT` | 以其他支付宝账号为操作对象，可能读取 / 占用 / 转移 / 干扰对方资源 | **小号档位必须落到中性值**（关闭、清空、不保护） |

### 隔离的中性值

`isNeutralValue` 只接受：`false`、`0`、`""`、空集合、空 Map，以及保护名单占位符 `AutoProtectAccounts`。
任何「开启 / 非零 / 非空」的取值都视为违反约束。

> 特别地：`CROSS_ACCOUNT` 行的 `altValue` **不允许是「不覆盖」**。否则小号会保留账号原有的旧配置，
> 隔离保证就落空了 —— 这是最容易踩的坑，已由单测锁定。

## 两套方案

### 小号档（ALT）

1. **模块全部启用**（`enable = true`），但逐个关闭跨账号功能开关 —— 不是简单地把整个模块关掉，
   这样小号仍能拿到纯本账号的进度收益。
2. **不收任何能量**：`AntForest.collectEnergy` 置为 `false`。
   原因：该开关在当前实现里同时门控「收自己」与「收好友」两条路径（`AntForest.kt` 的私有
   `collectEnergy(...)` 开头即判断它），无法只收自己的。要保证绝不碰大号能量，只能整体关闭。
3. **清空全部好友名单**（浇水、赠送、赠送能量雨、帮抽卡、送卡片、送麦子、帮喂、雇佣、贴罚单、
   丢肥料、邀请、助力、抢好友、清理海洋、合种浇水……）。
4. **关闭道具消耗**（双击卡 / 加速器 / 保护罩 / 炸弹卡 / 1.1 倍能量卡 / 隐身卡，以及炸弹卡、
   1.1 倍卡这两项本身以好友为对象）。
5. **关闭消耗型动作**（加饭卡、加速卡、特殊食品、新蛋卡、捐蛋、森林集市之外的兑换、自动捐赠……）。
6. **保留纯本账号的签到、任务与领取**（各模块签到、会员/芝麻信用/黄金票/商家服务/安心豆、
   森林任务与绿色行动、青春特权、保护地巡护、运动打卡、健康岛、农场收成、鱼池、AI 问答……）。
7. **双向保护名单**：把小号所在设备上**其他已载入的账号**写入
   `dontCollectList`（不收能量名单）、`alternativeAccountList`（周一保护）、`helpFriendCollectList`
   （复活能量名单），作为第二道保险。

### 大号档（MAIN）

1. 模块全部启用。
2. 开启各模块的收益与进度类能力，含面向好友的获取类玩法（见下表「大号开」列）。
3. 保持**纯干扰项**关闭：丢肥料、请走小摊、通知赶鸡、打赏好友、邀请好友摆摊、邀请开通新村。
   判断依据是「无实际收益、只影响他人」。
4. 名单类字段一律**不覆盖**：无法预知用户要给谁浇水、送谁道具，覆写只会破坏用户已有配置。
5. 同样写入双向保护名单，避免大号反手偷走小号的能量。

### 不干预项

以下设置与账号间资源无关，两档一律**保持账号当前值**：

- 调度与执行：执行间隔、任务轮数、定时执行/唤醒时间、只收能量时间、模块休眠、超时重启、异常等待与阈值、新接口开关。
- 日志与展示：record/runtime 日志、气泡提示与前缀偏移、状态栏禁删、抓包开关、Hook 数据转发、时区语言。
- 调优参数：各类查询/收取/重试间隔、尝试次数、循环间隔、游戏局数、睡觉时间、每日上限……
- AI 答题的第三方令牌（消耗的是大模型额度，不是大号资源）。

## 实现设计

| 文件 | 职责 |
| --- | --- |
| `model/AccountPresetPolicy.kt` | **纯策略**。档位枚举、作用域枚举、全量设置项表、中性值判定、隔离自检 `altViolations()`。无任何 Android 依赖，可直接单测。 |
| `model/AccountPreset.kt` | 应用器。写入 `ModelConfig` 字段 → `Config.save` → 广播宿主重载 → 落盘档位记录 `account_preset.json`。 |
| `ui/AccountPresetMenu.kt` | 交互入口。选账号 → 选档位 → 确认（可取消保护名单）→ 应用 → Toast 结果。 |
| `ui/screen/content/SettingsContent.kt` | 设置页新增「账号档位（大号 / 小号）」入口。 |

### 写入路径

沿用设置页既有链路，不新增任何配置读写机制：

```
AccountPreset.apply(tier, uid)
  ├─ Config.load(uid)                                  # 载入目标账号配置
  ├─ for (row in AccountPresetPolicy.overridesFor(tier))
  │     Model.getModelConfigMap()[modelCode]
  │         .getModelField(fieldCode)
  │         .setObjectValue(value)                     # 与 Web 设置页写值同源
  ├─ 保护名单三字段 ← 本机其他已载入账号
  ├─ Config.save(uid, force = true)
  ├─ 广播 com.eg.android.AlipayGphone.sesame.restart
  └─ 写 account_preset.json
```

### 影响面控制

- **只写登记过的字段**：`overridesFor(tier)` 过滤掉「不覆盖」的行；不存在的字段会记入 `skipped`
  并回报给用户，不会静默失败。
- **切换非当前账号时保护运行态**：目标账号 ≠ 当前运行账号时，先对内存配置做 JSON 快照，
  应用完毕后在 `finally` 里把快照写回 `Config.INSTANCE`，避免正在跑的账号读到别人的配置。
- **名单类字段的兜底**：即使用户在确认页取消勾选「保护其他账号」，也不会留下历史好友名单。

## 错误处理

- 单个字段找不到（版本差异）→ 记入 `skipped`，其余字段照常写入，结果里明确告知跳过数量。
- `Config.save` 失败 → 返回失败结果并记录日志，不广播重载、不写档位记录。
- 任意异常 → 捕获后返回失败结果，`finally` 中仍会恢复内存快照。

## 边界与已知取舍

1. **小号不再自动收自己的能量。** 这是隔离的代价，见上文第 2 条。若用户确需小号收自己的能量，
   需手动开启「收集能量」**并**确保大号在「不收能量 | 配置列表」里 —— 该组合会削弱隔离保证，
   因此不作为默认值。
2. **保护名单依赖「同一台设备上存在其他账号的配置目录」。** 大小号分别位于两台设备时，
   名单拿不到大号 userId，此时唯一保证是小号档位本身已关闭全部跨账号功能。
3. **档位记录只用于展示，不参与运行时判定。** 判定一律读配置字段本身，避免两套状态不一致。
4. **应用档位会覆盖用户手工调过的相关字段**，这是预设的固有语义，确认页已明确告知。
