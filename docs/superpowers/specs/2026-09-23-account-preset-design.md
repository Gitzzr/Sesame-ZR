# 账号档位（大号 / 小号）一键切换设计

> 状态：已实施（2026-09-23 ~ 09-24），已在 K50 完成端到端验证。
> 实施记录见 [`../plans/2026-09-23-account-preset.md`](../plans/2026-09-23-account-preset.md)（含各轮次与验证结果）。
>
> 本文档覆盖这个功能的**两层**：
> ①「档位切换」决定**哪些设置项写什么值**；②「批量启用功能」决定**把一个账号写进哪些好友名单**。
> 两者共用同一个入口与同一个应用器，因此写在一份设计里。

## 背景

本模块的绝大多数「蚂蚁系」功能都会以**好友**为操作对象：收好友能量、一键收取、Pk 榜收取、浇水、
合种浇水、雇佣好友小鸡、抢/训练好友、贴罚单、丢肥料、收取好友金币、帮好友抽卡、领好友礼盒……

当大号与小号互为好友、且两边都跑本模块时，默认配置会让它们**互相收取对方资源**。
更具体地说：小号开着「收集能量」「一键收取」时，会直接把大号已经成熟但未收取的能量球收走 ——
这是用户明确要避免的。当前版本没有任何机制阻止这件事，用户只能手工逐项关闭，既繁琐又容易漏。

另一层麻烦在各业务模块自己的「好友列表」设置（浇水给谁、赠送道具给谁、帮喂谁家的小鸡……），
一共 **26 项**：

1. 想把这些功能都指向**同一个**账号（典型场景：小号服务大号）时，要逐个功能打开列表去勾人，
   26 个项目里翻一遍，既繁琐又容易漏；
2. 这些名单**语义并不一致** —— 有的填进去表示"对这些人做某事"，有的表示"**不**对这些人做某事"
   （例如「不收能量」），还有一个是把对方从"被收取对象"改成"被保护对象"。填错方向会得到相反效果；
3. 「名单填了」也不等于生效：部分名单被一个**独立开关**门控（赠送道具要开「赠送道具」、
   一起拿饲料要开「一起拿饲料」…），开关关着时名单完全不起作用。

## 目标

**档位层**

- 提供两套**独立、完整**的配置方案：大号档（全功能）与小号档（隔离）。
- 一键切换，不需要逐项点开关。
- **硬约束：小号档位不得包含任何可能窃取或消耗大号资源（如能量）的设置项**，两套配置资源隔离、互不影响。
- 该约束必须是**可校验**的，而不是靠人工 review；后续新增设置项时若破坏约束，测试必须失败。

**批量启用层**

- 一键把**一批好友**套用到各功能的好友列表，免去逐项配置；勾选结果会记住，下次复用。
- 选中某个账号后，**完整展示该账号对应的全部功能**（26 项）供逐项勾选，**默认勾选全部推荐项**。
- 沿用既有的一键入口，不新增入口。
- 把"填对方向""开关要跟着开"这两件事写进**可执行的策略表与单测**，而不是靠人工记忆。

## 非目标

- 不做「按账号自动识别大小号」。档位由用户显式选择，避免猜测。
- 不改任何业务任务的实现逻辑，也不改 `Model` / `ModelField` 的既有结构。
- 不覆盖调度、日志、时区等基础设置（见下文「不干预项」）。
- 不做"自动识别哪个好友是大号"，关系由用户显式指定。
- 不在这一层配置具体参数（浇水克数、执行时间、阈值），那些仍在各模块的账号配置里。

> 说明：「按功能逐项挑选」一开始被列为非目标（首版是"全量套用 12 个名单"），
> 后按用户要求在轮次三改为**默认实现** —— 现在的交互就是逐项勾选。

## 核心概念

### 档位（PresetTier）

| 档位 | 代码 | 定位 |
| --- | --- | --- |
| 大号 | `main` | 主力号全功能档：开启各模块的收益与进度类能力 |
| 小号 | `alt` | 小号隔离档：关闭全部跨账号功能，只保留纯本账号操作 |

### 资源作用域（FieldScope）

每个设置项标注一个作用域，这是整套隔离保证的基石：

| 作用域 | 含义 | 档位处理 |
| --- | --- | --- |
| `SELF` | 只作用于本账号的数据与资源 | 两档都可自由开关 |
| `CROSS_ACCOUNT` | 以其他支付宝账号为操作对象，可能读取 / 占用 / 转移 / 干扰对方资源 | **小号档位必须落到中性值**（关闭、清空、不保护） |

### 隔离的中性值

`isNeutralValue` 只接受：`false`、`0`、`""`、空集合、空 Map，以及保护名单占位符 `AutoProtectAccounts`。
任何「开启 / 非零 / 非空」的取值都视为违反约束。

> 特别地：`CROSS_ACCOUNT` **开关类**行的 `altValue` **不允许是「不覆盖」**（`KEEP`）。
> 否则小号会保留账号原有的旧配置，隔离保证就落空了 —— 这是最容易踩的坑，已由单测锁定。
> 名单类与纯参数类的要求相反，见「三类字段的规则」。

## 两套档位

### 小号档（ALT）

1. **模块全部启用**（`enable = true`），但逐个关闭跨账号功能开关 —— 不是简单地把整个模块关掉，
   这样小号仍能拿到纯本账号的进度收益。
2. **不收任何能量**：`AntForest.collectEnergy` 置为 `false`。
   原因：该开关在当前实现里同时门控「收自己」与「收好友」两条路径（`AntForest.kt` 的私有
   `collectEnergy(...)` 开头即判断它），无法只收自己的。要保证绝不碰大号能量，只能整体关闭。
3. **关闭道具消耗**（双击卡 / 加速器 / 保护罩 / 炸弹卡 / 1.1 倍能量卡 / 隐身卡，以及炸弹卡、
   1.1 倍卡这两项本身以好友为对象）。
4. **关闭消耗型动作**（加饭卡、加速卡、特殊食品、新蛋卡、捐蛋、森林集市之外的兑换、自动捐赠……）。
5. **保留纯本账号的签到、任务与领取**（各模块签到、会员/芝麻信用/黄金票/商家服务/安心豆、
   森林任务与绿色行动、青春特权、保护地巡护、运动打卡、健康岛、农场收成、鱼池、AI 问答……）。
6. **名单类字段一律不由档位写入**（`KEEP`）—— 名单只由交互层的逐项勾选驱动。见「数据关联方式」。

> 首版曾在这里自动写「双向保护名单」，轮次四/五已移除：名单交给勾选后，
> 档位再写一遍会与「没勾就不动」矛盾，并让取消勾选失效。

### 大号档（MAIN）

1. 模块全部启用。
2. 开启各模块的收益与进度类能力，含面向好友的获取类玩法（见下表「大号开」列）。
3. 保持**纯干扰项**关闭：丢肥料、请走小摊、通知赶鸡、打赏好友、邀请好友摆摊、邀请开通新村。
   判断依据是「无实际收益、只影响他人」。
4. 名单类字段一律**不由档位写入**（`KEEP`）：无法预知用户要给谁浇水、送谁道具，覆写只会破坏用户已有配置。
5. **把本次选中的账号从排除类名单里移除** —— 大号需要收小号的能量。

### 全量设置项表（摘要）

完整清单在 `model/AccountPresetPolicy.kt` 的 `FIELDS` 中，共 **300 行** ——
16 个模块的总开关 + `ModelOrder` 所注册的 **284 个设置项**，其中 **79 行**为跨账号项。

> 轮次五（方案 A）删除了 `mainAccountList` / `subAccountList` 两个成员名单设置项，
> 规模由 302 行 / 286 项 / 80 行跨账号降为 300 行 / 284 项 / 79 行跨账号。
> 轮次六补了规模断言，改表会让单测变红以提醒同步文档口径。
>
> 覆盖率有据可查：逐模型的「`getFields()` 实际注册字段」与「策略表覆盖字段」做过双向比对，
> `ModelOrder` 里的 16 个模型全部零缺口。
>
> 唯一未纳入的是 `ManualTaskModel`（手动任务页的 6 个一次性触发开关）：
> 它**不在 `ModelOrder` 中注册**，不进入 `ModelConfigMap`，因此不属于档位配置的范畴。

### 不干预项

以下设置与账号间资源无关，两档一律**保持账号当前值**：

- 调度与执行：执行间隔、任务轮数、定时执行/唤醒时间、只收能量时间、模块休眠、超时重启、异常等待与阈值、新接口开关。
- 日志与展示：record/runtime 日志、气泡提示与前缀偏移、状态栏禁删、抓包开关、Hook 数据转发、时区语言。
- 调优参数：各类查询/收取/重试间隔、尝试次数、循环间隔、游戏局数、睡觉时间、每日上限……
- AI 答题的第三方令牌（消耗的是大模型额度，不是大号资源）。

## 数据基础：26 个好友名单字段

判定依据是**候选集**：只有候选集为 `AlipayUser::getList`（支付宝好友）的字段才算好友名单。
以下候选集一律排除：`AlipayBeach`（海域）、`CooperateEntity`（合种 ID）、`VitalityStore` /
`MemberBenefit` / `ParadiseCoinBenefit`（商品权益）、`AreaCode`（区划）、`ReserveEntity`（保护地）、
`farmFamilyOption`（家庭选项）、`listPropGroupOptions`（道具类型）。

### 按填充语义分四类

| 分类 | 数量 | 填进去的含义 | 字段 |
| --- | --- | --- | --- |
| `SERVICE` 服务类 | 11 | 对这些人做某件事，**消耗自己、利于对方** | 浇水、赠送能量雨、赠送道具、复活能量、帮喂小鸡、一起拿饲料、送麦子、帮抽卡、送卡片、助力好友（农场 / 新村各一） |
| `EXPLOIT` 索取/干扰类 | 10 | 对这些人做某件事，**损人利己** | 雇佣小鸡、通知赶鸡、抢好友、摆摊、贴罚单、丢肥料、邀请摆摊、邀请开通、请走小摊黑名单、清理好友海洋 |
| `EXCLUSION` 排除/豁免类 | 4 | 名单内的人**不做**该动作（填人 = 相反效果） | **不收能量**、遣返、家庭不邀请、请走小摊白名单 |
| `PROTECT` 保护改写类 | 1 | 把对方从「被收取对象」改成「被保护对象」 | `AntForest.alternativeAccountList`（显示名「小号列表」，实为复活能量保护名单） |

### 门控开关（"名单填了不生效"的坑）

| 名单 | 生效所需开关 |
| --- | --- |
| 赠送道具 | `AntForest.giveProp` |
| 赠送能量雨 | `AntForest.energyRain` |
| 一起拿饲料 | `AntFarm.getFeed` |
| **送麦子** | `AntFarm.visitAnimal`（挂在"到访小鸡送礼"下，容易误判为"无门控"） |
| 帮抽卡 | `AntDodo.collectToFriend` |
| 遣返 | `AntFarm.sendBackAnimal` |
| 排队/贴罚单/丢肥料/邀请摆摊/请走小摊/雇佣/通知赶鸡/抢好友/清理海洋 | 各自的同名开关 |
| 浇水、帮喂小鸡、送卡片、助力好友、不收能量 | 无门控，名单非空即生效 |

> 「选择 + 计数」型名单（浇水 / 帮喂小鸡 / 送麦子）的值是 `Map<userId, Int>`，
> 其中 `Int` 是**每日执行次数**，`≤ 0` 会被任务直接跳过 —— 一键填充必须给正数，取最保守的 **1**。

## 配置结构

### 1. 没有"成员名单"这一层

**曾经**在「基础」页签放过两个多选设置项（大号名单 / 小号名单）来存"谁是主号"。
2026-09-24 按用户决定删除（轮次五，方案 A），理由（三条都是硬事实）：

1. **没有任何运行时消费者** —— `task/` 与 `hook/` 对它们零引用，改它/清空它都不影响任何功能行为；
2. **内容与档位记录里的勾选完全重复** —— 记录里 `selection.<tier>` 的 **key 就是好友 uid**，
   成员集合可以直接推导；
3. **同一份配置里只有一个会被用到** —— 档位已经决定方向（小号档用大号那份、大号档用小号那份），
   而两个字段同属一份 `config_v2.json`，另一个恒为死数据。

取而代之：**"谁是这次要处理的大号/小号"完全由每次操作时选的好友表达**，
`selection` 的 key 既是"要处理的好友"也是"功能名单的成员"。只有一份数据，不会不一致。

### 2. 分类策略（`AccountFriendListPolicy`）

纯策略、无 Android 依赖，登记上面 26 项 + 门控 + 计数默认值，并给出两档的填充规则与隔离自检。

| 元数据 | 用途 |
| --- | --- |
| `kind`（服务 / 索取干扰 / 排除豁免 / 保护改写） | 分组展示、决定推荐与否、决定方向可用性 |
| `featureLabel` | 面向用户的方向化文案（"TA" = 列表中选中的账号），如「不收取 TA 的能量」 |
| `gateSwitches` | **勾了就必须连带写入的开关**（含动作选择器），否则名单填了不生效 |
| `countDefault` | 浇水 / 帮喂小鸡 / 送麦子三个「选择 + 计数」型的默认每日次数（1） |
| `effective` | 当前实现下是否真的生效；`false` 的项不进入推荐集，UI 标注「当前版本不生效」 |

## 数据关联方式

一键应用的写入规则 —— 不是"把名单铺上去"这么简单：

| 目标账号 | 排除类名单（不收能量…） | 服务类名单 | 索取/干扰类名单 | 门控开关 |
| --- | --- | --- | --- | --- |
| **小号推荐配置** | 写入**本次选中的好友** → 不偷大号 | 写入**本次选中的好友** → 只服务大号 | 不勾选就不动（开关保持关闭） | 勾选哪个功能就打开它的开关 |
| **大号推荐配置** | **移除本次选中的好友** → 大号要收小号能量 | 不动 | 不动 | 不动 |

两条硬约束：

1. **小号侧**：小号档不得把「本次选中的好友」以外的账号写进任何服务 / 索取名单 ——
   小号只对这些账号动手，不波及第三方好友。
2. **大号侧**（用户明确要求）：大号需要收取小号的能量，所以「不收能量」这类排除名单里
   **绝不能出现小号**。大号档不但不写，还会主动把选中的账号从现有名单里**剔除**。

`PROTECT` 类（复活能量体系）两档都**不碰**：小号档该体系整体关闭，填了也是死代码
（`isIsProtected` 里 `monday` 变量恒为 true，`helpFriendCollectList` 实际不可达）。

## 交互流程

沿用既有入口，四步：

```
设置页 →「账号档位（大号 / 小号）」
  → ① 选目标账号
  → ② 选【大号推荐配置】/【小号推荐配置】
  → ③ 名单 + 功能配置页（两级对话框，标题统一为「批量启用功能 · …」）
        一级：好友列表，每行 = 名称 + 「已配置 N 项 ▸ / 未配置 ▸」
              **点整行** → 进入二级（没有"是否列入名单"这一层）
        二级：该账号的**完整功能清单**（26 项，按 4 组分节）
              默认勾选全部推荐项；可「全选推荐 / 全不选」
  → ④ 确认页（汇总：将对 N 个账号批量启用 M 项功能）
  → 一键应用 → 落盘 + 广播重载
```

一级页的初始勾选来源（三级回退）：

1. `account_preset.json` 里该档位上次的勾选（过滤掉已不再是好友的 uid）；
2. 从未配过时，把「本机其他已载入账号」按推荐项预置 —— 同机双号开箱即用；
3. 都没有 → 空，用户自己勾。

### 文案边界（易误解，必须写清）

这一层**只决定「启用哪些功能」**：把账号写进该功能的**好友列表**并打开它的开关。
它**不配置参数** —— 浇水克数、执行时间、阈值等仍在各模块的账号配置里。

因此文案上有三条硬要求：

1. 对话框标题统一用「**批量启用功能 · …**」，不用「配置 TA 的功能」这类措辞；
2. **条目文案不得出现参数描述** —— 曾经写过「（每日 1 次）」，会让人以为次数在这里配，
   已删除；计数型的默认次数（1）改在页面说明里统一交代；
3. 确认页用**设置项原名**列出将写入的名单（如「浇水 | 好友列表」），而不是「给 TA 浇水」——
   前者直接告诉用户"哪个设置项会被写"，后者会让人以为在配这个功能。

第 ③ 步的勾选结果写进 `account_preset.json` 的 `selection.<档位>`，**下次直接复用** ——
这就是"免逐项配置"的落点。**没有独立的成员名单设置项**（见「配置结构」）。

> 一级列表**不能**再用设置页现成的 `ListDialog` —— 它的行点击被硬编码成"切换勾选"，
> 做不了下钻。改为自建 `ListView` + `BaseAdapter`：行内含一个不可点击的 `CheckBox`（状态展示）
> 与一个可点击的计数文本（进入二级）；裸 `ListView` 放进 `AlertDialog` 会因 `wrap_content`
> 塌成 0 高度，需套一层固定高度的容器。

## 逐项功能勾选

### 功能列表的数据来源

**一个好友名单字段 = 一项可对该好友启用的功能**，1:1，共 26 项，来源就是
[`AccountFriendListPolicy.FRIEND_LISTS`](../../../app/src/main/java/fansirsqi/xposed/sesame/model/AccountFriendListPolicy.kt)。

### 推荐项的判定规则

| 方向 | 默认勾选（推荐） | 刻意不勾 |
| --- | --- | --- |
| **小号推荐配置**（本机是小号，服务大号） | 服务 TA 的 10 项（剔除失效的「复活 TA 的能量」）+ 豁免项「不收取 TA 的能量」「不遣返 TA 的小鸡」= **12 项** | 对 TA 索取/干扰（不该对大号做损人动作）、独立体系、「不邀请进家庭」「不赶走摊位」（门控在小号档是关的，勾了也不生效，仍可手动勾） |
| **大号推荐配置**（本机是大号，管小号） | 只勾「帮 TA 复活能量」 | 任何排除项（**大号要收小号的能量**）、服务类（消耗大号资源）、索取类（会动小号的东西） |

> 「小号推荐配置」方向的这 12 项与改造前白名单制实际填充的集合**完全一致** → 向后兼容。

**方向可用性**：大号档下**排除/豁免类整体置灰不可选**，并在文案里写明原因
（「大号要收小号能量，不可选」）。这是约束在 UI 层的落地，防止用户勾出自我矛盾的配置。

### 保存与生效机制

**保存**：按「账号 → 档位 → 好友」保存，落在既有的 `account_preset.json`
（按账号隔离、已在读、无需新文件）：

```json
{
  "tier": "alt",
  "appliedAt": 0,
  "appliedCount": 196,
  "selection": {
    "alt":  { "2088412711917481": ["AntForest.waterFriendList", "..."] },
    "main": { }
  }
}
```

- **它只是"上次的勾选"，不是配置** —— 真正生效的配置是各功能自己的好友列表字段；
- 只能存 json —— `Set<String>` 型 `ModelField` 表达不了"按好友分别勾选"的嵌套结构；
- 按**档位**分键（而不是按"哪份名单"）：两个方向共用一份记录，本次方向写新值、
  另一个方向沿用上次，互不覆盖；
- `tier` 保留（UI 用来显示"当前：小号档"），但**不再存可推导的 `tierLabel`**，
  也不再有 `protectedAccounts`（那就是旧的"大号名单"）；
- 首次进入默认全勾推荐项（点进某个好友时按推荐预置）；之后沿用上次保存的勾选
  （一级页有「按推荐重置」可一键回到推荐）。

**生效**：应用时不再"全量套用"，而是**按勾选聚合**：

1. 只遍历 `selection` 里**值非空**的好友（值为空 = 不处理）；
2. 把「每个好友勾了哪些功能」**反转**成「每项功能被哪些好友勾选」；
3. 对每项被勾选的功能：写入其名单字段（计数型补默认次数）+ **连带写入 `gateSwitches`**；
4. **未被勾选的功能一律不动**（规则见下方「三类字段」）；
5. 某账号一项都没勾 → 它对任何名单都不产生写入；
6. 大号档另有强约束：无论勾选如何，都把**选中的账号从排除类名单里移除**。

> 语义因此收敛为「**勾了就填、填了就开开关；没勾就不动**」，
> 原先的 `altFillable` 预筛、独立的白名单开关表、`WriteMainAccountList` 特殊路径都被删掉，
> 规则更少也更好验证。

#### 三类字段的规则（反直觉，必须记牢）

`AccountPresetPolicy.FIELDS` 里的行按性质分三类，而**小号档对它们的要求是相反的**：

| 类别 | 数量 | 小号档要求 | 理由 |
| --- | --- | --- | --- |
| **开关类**（布尔 / 动作选择器） | 绝大多数 | 必须是中性值，**不允许「不覆盖」** | 开关是"阻止行为"的最后一层；保留账号原值等于没隔离 |
| **名单类**（26 个好友名单） | 26 | **必须「不覆盖」** | 名单只由勾选驱动。若档位也写它：① 未勾选的名单被静默清空，与"没勾就不动"矛盾；② 用户取消勾选后档位写的值仍留下 —— **取消失效** |
| **纯参数类** | 1（浇水克数） | **必须「不覆盖」** | 0 不是合法值（浇水克数只有 10/18/33/66），档位设 0 会把参数改坏 |

三条自检一一对应：`altViolations()`（开关类）、`listRowsNotKeep()`（名单类）、
`PLAIN_PARAM_ROWS`（参数类例外，并由单测保证它确实是「不覆盖」）。

> ⚠️ **行为层的隔离不依赖名单，而是由开关承担。** 小号档 `collectEnergy = false`，
> 所以即使「不收能量」名单是空的、里面还有别人，小号也一颗能量都收不到；
> 名单只是"想精确控制"时才用的工具。

> ⚠️ **无门控的 4 类名单，取消勾选 ≠ 停用**：浇水 / 帮喂小鸡 / 送卡片 / 助力好友
> 没有独立开关（名单非空即生效），"不动"它们意味着**已有名单会继续执行**。
> 要停用只能到该功能的账号配置里清空名单。

## 实现设计

| 文件 | 职责 |
| --- | --- |
| `model/AccountPresetPolicy.kt` | **纯策略**。档位枚举、作用域枚举、全量设置项表、中性值判定、隔离自检。无任何 Android 依赖，可直接单测。 |
| `model/AccountFriendListPolicy.kt` | **纯策略**。26 个好友名单的分类、门控、计数默认值、推荐规则。 |
| `model/AccountPreset.kt` | 应用器。写入 `ModelConfig` 字段 → `Config.save` → 广播宿主重载 → 落盘档位记录 `account_preset.json`。 |
| `ui/AccountPresetMenu.kt` | 交互入口。选账号 → 选档位 → 一级好友列表 → 二级功能清单 → 确认 → 应用 → Toast 结果。 |
| `ui/screen/content/SettingsContent.kt` | 设置页新增「账号档位（大号 / 小号）」入口。 |

### 写入路径

沿用设置页既有链路，不新增任何配置读写机制：

```
AccountPreset.apply(tier, uid, selection)
  ├─ ensureModelRegistry()                             # 注册表为空则先 Model.initAllModel()
  ├─ Config.load(uid)                                  # 载入目标账号配置
  ├─ for (row in AccountPresetPolicy.overridesFor(tier))          # 第 2 步：静态档位表
  │     Model.getModelConfigMap()[modelCode]
  │         .getModelField(fieldCode)
  │         .setObjectValue(value)                     # 与 Web 设置页写值同源
  ├─ for ((功能, 好友们) in aggregateSelection(selection))        # 第 3 步：按勾选聚合
  │     写名单字段 [+ 连带写 gateSwitches]
  ├─ if (tier == MAIN) 排除类名单 ← 现有名单 - 选中的好友           # 第 4 步
  ├─ Config.save(uid, force = true)
  ├─ 广播 com.eg.android.AlipayGphone.sesame.restart
  ├─ 写 account_preset.json
  └─ finally: 恢复当前运行账号的内存配置
```

### 影响面控制

- **只写登记过的字段**：`overridesFor(tier)` 过滤掉「不覆盖」的行；不存在的字段会记入 `skipped`
  并回报给用户，不会静默失败。
- **名单只由勾选驱动**：静态档位表里 26 个名单行全是 `KEEP`，不会被档位无条件改写
  （否则「没勾就不动」与「取消勾选」都会失效）。
- **切换非当前账号时保护运行态**：目标账号 ≠ 当前运行账号时，先对内存配置做 JSON 快照，
  应用完毕后在 `finally` 里把快照写回 `Config.INSTANCE`，避免正在跑的账号读到别人的配置。
- **注册表必须先就绪**：`Model.initAllModel()` 只被 `ApplicationHook` 与三个设置 Activity 调用过，
  `MainActivity` 没有。在模块自己的进程里从主界面进来时注册表为空，此时 `Config.save`
  会把**空配置覆盖到账号的 `config_v2.json`**，等于清空用户配置。`ensureModelRegistry()`
  负责先初始化，仍为空则中止并回报。
- **不再有"自动写入本机其他账号"的行为**：首版会把本机其他已载入账号写进保护名单，
  轮次五已移除（会破坏用户已有配置）。`otherAccountIds()` 现在只用于
  ①账号列表兜底、②首次进入时预置勾选。

## 错误处理

- 单个字段找不到（版本差异）→ 记入 `skipped`，其余字段照常写入，结果里明确告知跳过数量。
- `Config.save` 失败 → 返回失败结果并记录日志，不广播重载、不写档位记录。
- 任意异常 → 捕获后返回失败结果，`finally` 中仍会恢复内存快照。
- 好友列表读不到（`friend.json` 不存在或为空）→ Toast 提示，跳过错勾选直接进确认页。

## 边界与已知取舍

1. **小号不再自动收自己的能量。** 这是隔离的代价，见上文第 2 条。若用户确需小号收自己的能量，
   需手动开启「收集能量」**并**确保大号在「不收能量 | 配置列表」里 —— 该组合会削弱隔离保证，
   因此不作为默认值。
2. **跨设备场景下拿不到对方 userId。** 大小号分处两台设备时，「本机其他账号」为空，
   首次进入的预置勾选不会生效，需要用户手动在好友列表里指定；此时唯一保证是小号档位本身
   已关闭全部跨账号功能。
3. **档位记录只用于展示与预置，不参与运行时判定。** 判定一律读配置字段本身，避免两套状态不一致。
4. **应用档位会覆盖用户手工调过的相关字段**，这是预设的固有语义，确认页已明确告知。
5. **名单字段的写入是"覆盖"，不是"追加"。** 对某个功能而言，最终名单 = 勾选了该功能的那些好友；
   不会与原有名单合并。一天内多次套用是幂等的。
6. **`AntForest.alternativeAccountList` 的显示名也叫「小号列表」**，但它与"谁是我的小号"
   毫无关系（它是复活能量保护名单）。文档与文案里一律用「TA」指代"当前正在配置的那个账号"，
   避免与它混淆。
7. **`AntForest.helpFriendCollectList`（复活能量 | 好友列表）是死代码**：
   `isIsProtected` 里 `monday` 变量恒为 true，永远走不到读它的分支。
   已标记 `effective = false`，不进推荐集，UI 标注「当前版本不生效」。
